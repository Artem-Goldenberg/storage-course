#

512e / 4Kn
Накопители с логическим сектором 512 байт и физическим 4 КиБ или с сектором 4 КиБ в обоих случаях. 02

A

address_space
Страничный кэш одного файла: XArray фолио плюс его address_space_operations. 05
AHCI (Advanced Host Controller Interface)
Программный интерфейс управления хост-контроллером SATA. 02
API (Application Programming Interface)
Программный интерфейс, через который программа использует другой компонент: операции, аргументы, результаты и их смысл. 06
AUTH_SYS
Учётные данные RPC: числовые uid, gid и до 16 групп, которым сервер просто верит. 06

B

B+-дерево (B+tree)
B-дерево, в котором все записи хранятся в листьях, а во внутренних узлах лежат только разделительные ключи; листья связаны между собой для обхода диапазонов. 04
B-link-дерево (B-link tree)
Вариант B+-дерева со ссылками на правого соседа, благодаря которым читатели могут продолжать работу, пока узел расщепляется. 04
B-дерево (B-tree)
Сбалансированное дерево поиска с множеством ключей в каждом узле, в котором все листья находятся на одной глубине. 04
balance_dirty_pages
Торможение пишущих процессов: они засыпают, когда объём грязной памяти превышает лимит. 05
bio / struct bio (block I/O)
Описание операции блочного ввода-вывода (block I/O) в ядре Linux. Для чтения или записи содержит устройство, диапазон секторов, буферы памяти, куда нужно поместить данные или откуда их взять, и функцию, которую нужно вызвать по завершении операции. 02
bio_vec
Структура C в Linux, описывающая один сегмент памяти для блочного ввода-вывода: начальную страницу, смещение в байтах и длину. bio ссылается на список таких сегментов. 02
blk-mq (multi-queue block I/O)
Многоочередной блочный ввод-вывод Linux: программные очереди, связанные с процессорами, направляют запросы в аппаратные очереди отправки устройства. 02

C

COMPOUND
Единственная процедура NFSv4: список операций, которые выполняются по порядку, пока одна из них не завершится ошибкой. 06
CRUSH
Детерминированная функция размещения Ceph по взвешенной иерархии доменов отказа; на каждом уровне используется straw2. 09

D

Dentry
Кэшированная связь пары (родительский каталог, имя) с inode или с отсутствием файла. 05
Discard / TRIM
Команда, которая сообщает устройству, что диапазон LBA больше не содержит нужных данных. 02
DMA (Direct Memory Access)
Прямой доступ к памяти: устройство передаёт данные в ОЗУ или из него без копирования каждого байта процессором. Процессор по-прежнему настраивает передачу. 08
Doorbell
Запись в отображённый в память регистр, которая сообщает сетевой карте (или NVMe-накопителю), что появилась новая работа. 08

E

errno
Код ошибки, свой у каждого потока. Ядро возвращает −errno, а обёртка libc превращает это в −1 и значение errno. 01
errseq_t
Счётчик ошибок обратной записи на уровне файла. Благодаря ему fsync сообщает о каждой ошибке один раз для каждого открытого файла. 05
ESTALE
Устаревший хэндл файла (stale file handle): сервер больше не узнаёт хэндл, обычно потому, что файл удалён или заменён. 06

F

FLUSH / FUA (Force Unit Access)
FLUSH делает предшествующие записи из кэша надёжно сохранёнными. FUA, Force Unit Access, требует сохранить конкретную запись на устойчивом носителе до её завершения. FLUSH — название команды, а не аббревиатура. 02
FRWR
Быстрая регистрация (fast registration): регистрация и аннулирование памяти рабочими запросами для каждой операции ввода-вывода, без системного вызова. 08
fsync / fdatasync
Дождаться, пока данные файла и все его метаданные (или только необходимые) окажутся на стабильном носителе, включая сброс кэша устройства. 05
FTL (flash translation layer)
Прошивка SSD, которая отображает LBA на страницы флеш-памяти и никогда не перезаписывает данные на месте. 02
FUSE (Filesystem in Userspace)
Интерфейс Linux для реализации файловой системы в процессе пользовательского пространства; ядро передаёт ему файловые запросы. 05

G

GRO (Generic Receive Offload)
Ядро объединяет совместимые принятые пакеты в более крупную единицу для дальнейшей обработки протокола. 08

H

HDD (Hard Disk Drive)
Жёсткий диск хранит данные магнитным способом на вращающихся пластинах; для доступа к ним перемещаются головки. 02
HPC (High-Performance Computing)
Высокопроизводительные вычисления: крупные вычислительные задачи, часто распределённые по множеству узлов кластера. 08
htree
Индекс каталога в ext4: B-дерево по хешу имени, корень которого (dx_root) лежит в блоке 0 каталога. 04

I

I/O (Input/Output)
Ввод-вывод: передача данных между программой, памятью и устройствами, включая чтение и запись файлов. 01
Inode (индексный дескриптор)
Запись фиксированного размера с типом файла, правами доступа, размером, временными метками, счётчиком ссылок и картой блоков. 03
IOMMU (Input/Output Memory Management Unit)
Аппаратный блок, который преобразует используемые устройством DMA-адреса в физические адреса памяти и ограничивает доступ устройства к памяти. 08
iSCSI (Internet SCSI)
Протокол передачи команд SCSI поверх TCP/IP: удалённое хранилище представляется клиенту блочным устройством. 02

J

jbd2 (Journaling Block Device 2)
Уровень журналирования Linux, используемый ext4. Фиксирует изменения метаданных транзакциями и воспроизводит зафиксированные транзакции после сбоя. 03

L

LBA (logical block address)
Логический адрес блока: номер сектора, по которому адресуется устройство, считая с 0. 02
LDLM
Распределённый менеджер блокировок Lustre. Клиент может кэшировать только те диапазоны байтов и метаданные, на которые держит блокировки. 09
LRU (Least Recently Used)
Политика вытеснения, предпочитающая данные, к которым дольше всего не обращались. При освобождении памяти Linux оценивает давность обращений с помощью списков или поколений. 05
LSM-дерево (Log-Structured Merge-Tree)
Дерево со слиянием журнальных структур: накапливает записи в памяти и сливает отсортированные файлы в фоне вместо обновления страниц дерева на месте. 04

M

Maple tree
B-дерево диапазонов адресов в памяти ядра Linux; на нём построена карта памяти процесса. 04
MTU (Maximum Transmission Unit)
Максимальный размер пакета, передаваемого по каналу без фрагментации на соответствующем сетевом уровне. В Ethernet значение IP MTU не включает заголовок Ethernet. 08

N

NAND flash
Энергонезависимая память, используемая в SSD. Название NAND связано с логической схемой NOT-AND («И-НЕ»); данные записываются страницами, а стираются более крупными блоками. 02
NAPI
Механизм сетевой подсистемы Linux, сочетающий уведомления через прерывания с опросом для пакетной обработки трафика. В текущей документации ядра NAPI используется как имя, а не как аббревиатура. 08
NAS (Network-Attached Storage)
Хранилище с доступом по сети на уровне файлов, например через NFS или SMB. 06
NFS (Network File System)
Протокол сетевой файловой системы: клиент работает с файлами на сервере через обычные файловые операции, например open, read и write. 06
NIC (Network Interface Card)
Сетевой адаптер, который отправляет и принимает кадры и передаёт данные пакетов между сетью и памятью компьютера. 08
NVMe (Non-Volatile Memory Express)
Интерфейс доступа к энергонезависимой памяти накопителя. Локальные устройства NVMe используют PCI Express, а NVMe over Fabrics переносит команды по сети. NVMe — название интерфейса, а не самой флеш-памяти. 02
NVMe-oF (NVMe over Fabrics)
Передача NVMe по сети, например поверх RDMA или TCP, для доступа к удалённому хранилищу с помощью команд NVMe. 08

O

O_APPEND
Флаг открытия, который перед каждой записью атомарно переносит смещение в конец файла. Атомарен только на локальных файловых системах, но не в NFS. 01
O_CLOEXEC
Флаг, который автоматически закрывает дескриптор при execve. 01
O_DIRECT
Флаг открытия для DMA между буфером пользователя и устройством в обход страничного кэша. Требует выровненных буферов и смещений. 05
ONC RPC (Open Network Computing Remote Procedure Call)
RPC — Remote Procedure Call, удалённый вызов процедуры через обмен сообщениями. ONC RPC — используемый NFS механизм таких вызовов (RFC 5531); идентификатор транзакции xid связывает ответ с вызовом. 06

P

PCIe (PCI Express)
Peripheral Component Interconnect Express: последовательное соединение компьютера с устройствами, например накопителями NVMe и сетевыми адаптерами. 02
pNFS (parallel NFS)
Параллельный NFS: возможность NFSv4.1, при которой сервер метаданных выдаёт раскладки, а клиенты обращаются к серверам данных напрямую. 06
POSIX (Portable Operating System Interface)
Семейство стандартов интерфейсов операционной системы, включая файловые операции и требования к их поведению. 01

R

RBD (RADOS Block Device)
Блочное хранилище Ceph: виртуальный диск, данные которого хранятся в виде объектов RADOS. 09
RCU (Read-Copy Update)
Механизм синхронизации: читатели обращаются к общим данным, изменения публикуются отдельно, а старые версии освобождаются после завершения читателей, которые могли их использовать. 04
RCU-обход (RCU walk)
Поиск пути по dcache без блокировок. Если что-то меняется, он откатывается к обходу со счётчиками ссылок. 05
RDMA (Remote Direct Memory Access)
Удалённый прямой доступ к памяти: сетевой адаптер передаёт данные напрямую в зарегистрированную память другой машины или из неё. При односторонних операциях её процессору не нужно обрабатывать каждую передачу. 08
Reliable Connected (RC)
Транспорт RDMA с подтверждаемой доставкой по порядку между одной парой QP. Именно его используют протоколы хранения. 08
RGW (RADOS Gateway)
Шлюз объектного хранения Ceph, предоставляющий S3- и Swift-совместимые интерфейсы поверх RADOS. 09
RoCE v2
RDMA поверх Ethernet в пакетах UDP/IP (порт назначения 4791). Полагается на PFC и ECN/DCQCN. 08
RPC-over-RDMA
Формат кадров по RFC 8166, который переносит ONC RPC, а значит, и NFS поверх RDMA, с кредитами и списками чанков. 08
RPCSEC_GSS
Безопасность RPC на основе Kerberos: krb5 проверяет подлинность, krb5i добавляет контроль целостности, krb5p — шифрование. 06

S

SAN (Storage Area Network)
Сеть хранения, предоставляющая компьютерам доступ к блочным устройствам; файловую систему на них обслуживает сам компьютер. 06
SAS (Serial Attached SCSI)
Последовательный интерфейс передачи команд SCSI, часто используемый для серверных накопителей. 02
SATA (Serial ATA)
Serial Advanced Technology Attachment: последовательный интерфейс подключения накопителей, в том числе жёстких дисков и SSD. 02
SCSI (Small Computer System Interface)
Семейство стандартов, включающее команды для накопителей. Уровень SCSI в Linux обслуживает разные виды дисков, не только устройства с физическим подключением SCSI. 02
SSD (Solid-State Drive)
Твердотельный накопитель: устройство хранения без движущихся механических частей, обычно на флеш-памяти NAND. 02
Stateid
16-байтовый идентификатор NFSv4 для открытия, блокировки, делегирования или раскладки. Передаётся в READ, WRITE, LOCK и CLOSE. 06
super_block
Объект в памяти для одного смонтированного экземпляра файловой системы; содержит её super_operations. 05

T

TSO (TCP Segmentation Offload)
Сетевой адаптер разбивает большой исходящий буфер TCP на пакеты, уменьшая работу процессора в расчёте на пакет. 08

V

VFS (virtual file system)
Виртуальная файловая система: уровень ядра, который превращает файловые системные вызовы в вызовы таблиц операций конкретной файловой системы. 05

X

XArray
Корневое дерево (radix tree), которое индексирует фолио файла по номеру страницы. 05
XDR (External Data Representation)
Внешнее представление данных: машинно-независимая кодировка аргументов и результатов RPC, использующая порядок байтов big-endian и выравнивание по четыре байта (RFC 4506). 06

А

Адрес inode по номеру (inode number arithmetic)
группа = (ino − 1) / inodes_per_group; смещение в байтах получается из блока таблицы inode этой группы и размера inode. 03
Аренда (lease)
Срок (в Linux по умолчанию 90 с), в течение которого состояние клиента NFSv4 остаётся действительным без продления. 06
Атомарная замена файла (atomic replace)
Записать временный файл, сделать ему fsync, вызовом rename поставить его на место целевого и сделать fsync каталогу. 05
Атрибут изменения (change attribute)
Значение NFSv4, которое сервер обязан менять при каждом изменении файла. В Linux за ним стоит i_version. 07

Б

Блочное устройство (block device)
Устройство, которое адресуется как массив секторов фиксированного размера; их можно читать и писать в любом порядке. 02

В

Верификатор записи (write verifier)
8-байтовое значение в ответах WRITE и COMMIT. Оно меняется при перезапуске сервера и сообщает клиентам, что незафиксированные данные нужно отправить заново. 06

Г

Глупое переименование (silly rename)
NFS-клиент переименовывает удалённый файл, который у него ещё открыт, в .nfsXXXX и удаляет его при последнем закрытии. 07
Группа блоков (block group)
Срез файловой системы ext4 фиксированного размера со своими битовыми картами и своей частью таблицы inode. 03
Группа размещения (PG)
Хеш-корзина объектов Ceph внутри пула. CRUSH отображает на OSD группы размещения, а не отдельные объекты. 09
Грязная страница (dirty page)
Кэшированные данные, изменённые в ОЗУ и ещё не записанные на устройство. 05

Д

Делегирование (delegation)
Обещание сервера, которое позволяет клиенту открывать и кэшировать файл, не спрашивая сервер снова, пока тот не пришлёт CB_RECALL. 07
Дерево экстентов (extent tree)
B+-дерево экстентов в ext4, корень которого лежит в 60-байтовом поле i_block inode. 04
Дескриптор группы (group descriptor)
Запись о группе блоков: номера блоков её битовых карт и её таблицы inode. 03
Дыра (hole)
Диапазон блоков файла, не покрытый ни одним экстентом; при чтении он возвращает нули. 03

Ж

Жёсткая ссылка (hard link)
Ещё одна запись каталога для того же inode; число таких записей хранится в i_links_count. 03

З

Запись каталога (directory entry)
Запись переменной длины в блоке каталога, связывающая имя с номером inode. 03

И

Изоляция узла (fencing)
Обезвреживание узла, который считается мёртвым (выключение питания, отключение от хранилища, блок-лист, эпоха), прежде чем забрать его работу. 09

К

Кворум (quorum)
Изменения одобряет большинство небольшой группы нечётного размера, поэтому при разделении сети вносить их может не больше одной стороны. 09
Копирование на стороне сервера (server-side copy)
Операция NFSv4.2 COPY, которую запускает copy_file_range(): сервер копирует данные, не пропуская их через клиента. 06
Копирование при записи (COW)
Блок никогда не перезаписывается на месте: новая версия пишется в другое место, и указатели на неё обновляются вплоть до корня. 03
Коэффициент ветвления (fanout)
Сколько потомков может быть у одного узла дерева: размер узла, делённый на размер записи. 04
Кэш атрибутов (attribute cache)
Кэш атрибутов файлов в NFS-клиенте. Ему доверяют в течение тайм-аута, который подстраивается между acregmin и acregmax (от 3 до 60 с). 07
Кэш повторных запросов (duplicate request cache, DRC)
Кэш недавних ответов на сервере. С его помощью сервер отвечает на повторно отправленные неидемпотентные запросы. 06

Н

Негативный dentry (negative dentry)
Кэшированная запись о том, что имени не существует, чтобы повторные промахи не доходили до файловой системы. 05

О

Обратная запись (writeback)
Потоки сброса (flusher) записывают грязные фолио на устройство при достижении порогов, по возрасту или по fsync. 05
Описание открытого файла (open file description)
Объект ядра (struct file), который создаёт open(). Хранит смещение и флаги состояния; после dup и fork становится общим. 01
Освобождение памяти (reclaim) / kswapd
Освобождение памяти: чистые страницы отбрасываются, грязные записываются, анонимные уходят в swap. 05
Отложенное выделение (delayed allocation)
Выбор блоков диска во время обратной записи, а не в момент write(), чтобы распределитель видел более длинные участки. 03
Очередь завершений (CQ)
Очередь, в которую сетевая карта помещает запись о завершении каждого выполненного рабочего запроса. 08

П

Пара очередей (QP)
Очередь отправки плюс очередь приёма: конечная точка RDMA. Перед использованием она должна пройти состояния RESET → INIT → RTR → RTS. 08
Пара очередей NVMe (NVMe queue pair)
Кольцевые буферы запросов и завершений в ОЗУ хоста, которыми управляют записи в doorbell. RDMA использует ту же модель. 02
Период отсрочки (grace period)
Окно после перезапуска сервера, когда клиенты могут только восстанавливать открытия и блокировки, которые держали до перезапуска. 06
Помехоустойчивое кодирование (erasure coding)
k чанков данных плюс m кодовых чанков. Переживает потерю любых m чанков при накладных расходах (k+m)/k от сырого объёма. 09
Порог встроенной передачи (inline threshold)
Наибольшее сообщение RPC, которое отправляется обычной операцией SEND. Для всего, что больше, нужны чанки. 08

Р

Разреженный файл (sparse file)
Файл с дырами: диапазонами без дисковых блоков, которые читаются как нули. 01
Регион памяти (MR)
Зарегистрированный закреплённый буфер. Его lkey позволяет локальным рабочим запросам использовать буфер, а rkey даёт к нему доступ удалённой стороне. 08

С

Системный вызов (system call)
Запрос пользовательской программы к ядру, сделанный инструкцией syscall: номер в rax, аргументы в регистрах. 01
Согласованное хеширование (consistent hashing)
Размещение на хеш-кольце, при котором добавление узла перемещает лишь около 1/(N+1) данных. 09
Согласованность close-to-open (close-to-open consistency)
Открытие, сделанное после того, как другой клиент закрыл файл, видит записи этого клиента. Это контракт NFS. 07
Страничный кэш (page cache)
Копия содержимого файлов в ОЗУ ядра, общая для read, write и mmap. 05
Суперблок (superblock)
Запись размером 1 КиБ с байта 1024: размеры, счётчики и возможности файловой системы, а также магическое число 0xEF53. 03

Т

Таблица операций (operation table)
Структура указателей на функции, которую заполняет файловая система, чтобы VFS могла её вызывать. 05
Таблица слотов сессии (session slot table)
Порядковые номера и кэшированные ответы для каждого слота в NFSv4.1, которые дают семантику «ровно один раз» (exactly-once). 06

У

Удалённый, но открытый файл
inode без единого имени, который продолжает жить, пока открыт дескриптор, и занимает место до последнего закрытия. 01
Упреждающее чтение (readahead)
Чтение данных файла до того, как их запросили. Запускается последовательным доступом. 05
Усиление записи (write amplification)
Отношение объёма записей во флеш-память к объёму записей хоста. Растёт из-за сборки мусора. 02

Ф

Файловый дескриптор (fd)
Небольшое целое число, индекс в таблице открытых файлов процесса. 01
Фолио (folio)
Непрерывная последовательность страниц длиной в степень двойки, которой управляют как единым целым (Linux 5.16 и новее). 05

Х

Хэндл файла (file handle)
Непрозрачный идентификатор файла, который выдаёт сервер (до 64 байт в v3, до 128 в v4). Обычно кодирует id файловой системы, inode и номер поколения. 06

Ч

Чанк чтения / записи / ответа (read / write / reply chunk)
Память, которую объявляет клиент, чтобы сервер через RDMA забирал из неё большие аргументы или помещал в неё большие результаты и длинные ответы. 08
Чередование (striping)
RAID 0 из байтов файла по нескольким серверам данных. Задаётся размером полосы (stripe size) и числом полос (stripe count). 09
Чтение-изменение-запись (read-modify-write)
Чтение целой единицы ради изменения её части. Возникает при мелких или невыровненных записях. 02

Э

Экстент (extent)
Непрерывный участок блоков, описанный тройкой (блок файла, длина, блок диска). 03
