From open() to RDMA

How a file really works: from the C call that opens it, down through the kernel to the blocks on a disk, then out across the network to NFS servers, RDMA fabrics and clusters of machines. Every lesson ends with a lab you run yourself.

Read it top to bottom. A read() starts in your program, crosses into the kernel, and ends at a disk: your own, or one on a server across the wire. The layers below the VFS are interchangeable, which is why an NFS mount behaves like a local directory. Each box links to the lesson that opens it up.

The route

Top of the stack first, then the bottom, then the kernel that joins them, then out across the network. Lessons 06–09 lean on everything before them, so take them in order.

  1. 01 · user spacelab 01-fds

    Syscalls and file descriptors

    What a syscall is, the file API in C, and the three tables behind every fd: descriptor table, open file description, inode.

  2. 02 · blocklab 02-blocks

    Block devices and addressing

    Sectors, LBAs and blocks; HDDs, SSDs and NVMe queues; the block layer; write caches, FLUSH and FUA.

  3. 03 · filesystemlab 03-ondisk

    Inside an ext4 image

    Superblock, block groups, inodes, extents, directories and the journal, read byte by byte with a walker you compile.

  4. 04 · filesystemlab 04-btrees

    B-trees, really

    Why disks want wide, shallow trees, and where they live: ext4 extents and htree, XFS, btrfs, databases. With a live B+tree.

  5. 05 · kernellab 05-cache

    The VFS and the caches

    How read() dispatches, the dcache and page cache, writeback, fsync, O_DIRECT, and what "durable" means.

  6. 06 · networklab 06-nfs (A)

    NFS from v3 to 4.2

    RPC and file handles, stateless v3, stateful v4, sessions and pNFS in 4.1, and every 4.2 feature mapped to the syscall that uses it.

  7. 07 · networklab 06-nfs (B)

    Caching across the network

    Attribute timeouts, close-to-open, unstable writes and COMMIT, delegations and recalls, FS-Cache, and how other systems keep caches coherent.

  8. 08 · networklab 07-rdma

    RDMA and NFS over RDMA

    Verbs, queue pairs and memory registration; InfiniBand, RoCE and iWARP; how RPC-over-RDMA moves NFS data with read and write chunks.

  9. 09 · networklab 08-distributed

    Distributed filesystems

    Metadata servers and striping, CRUSH and consistent hashing, replication and erasure coding, locks and leases, failure and recovery.

Running the labs

The labs live in ~/storage-course/labs/ in your WSL home, one folder per lab, each with a README.md. Most need nothing but the compiler and tools you already have, and run without root: the filesystem labs build ext4 images inside ordinary files.

no root01 descriptors, 02 superblock, 03 ext4 walker, 04 extent and directory trees, 05 page cache, 08 placement.
sudo06 NFS: installs an NFS server and mounts it over loopback inside WSL.
a Linux VM07 RDMA: the WSL kernel has no RDMA support, so soft-RoCE runs in an Ubuntu VM.

Optional tools that make the labs richer:

$ sudo apt install strace tcpdump tshark xfsprogs fio \
      nfs-kernel-server nfs-common
