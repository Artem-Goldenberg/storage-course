Glossary

Every term the course defines, in one place. The chip after each definition is the lesson that explains it; its colour is the layer of the stack the term lives in.

98 terms
# A B C D E F G H I J L M N O P Q R S V W X

No term matches. Try a shorter word.

#

512e / 4Kn
Drives with 512-byte logical and 4 KiB physical sectors, or 4 KiB for both. 02

A

address_space
One file's page cache: an XArray of folios plus its address_space_operations. 05
Atomic replace pattern
Write a temp file, fsync it, rename it over the target, fsync the directory. 05
Attribute cache
The NFS client's cache of file attributes, trusted for a timeout that adapts between acregmin and acregmax (3 to 60 s). 07
AUTH_SYS
RPC credential that sends a numeric uid, gid and up to 16 groups, which the server simply trusts. 06

B

balance_dirty_pages
Throttling that makes writers sleep when dirty memory exceeds its limit. 05
bio
The block layer's I/O descriptor: device, start sector, memory segments and a completion callback. 02
B-link tree
A B+tree variant with right-sibling links, so readers can carry on while a node splits. 04
blk-mq
The multi-queue block layer: per-CPU software queues mapped onto the device's hardware queues. 02
Block device
A device addressed as a fixed-size array of sectors that can be read and written in any order. 02
Block group
A fixed-size slice of an ext4 filesystem with its own bitmaps and its part of the inode table. 03
B-tree
A balanced search tree with many keys per node, where all leaves are at the same depth. 04
B+tree
A B-tree that keeps all records in the leaves and only separator keys in the internal nodes; leaves are linked for range scans. 04

C

Change attribute
An NFSv4 value the server must change on every modification of a file; Linux backs it with i_version. 07
Close-to-open consistency
An open made after another client's close sees that client's writes. The NFS contract. 07
Completion queue (CQ)
Where the NIC posts a completion entry for each finished work request. 08
COMPOUND
The single NFSv4 procedure: a list of operations run in order until one fails. 06
Consistent hashing
Placement on a hash ring, where adding a node moves only about 1/(N+1) of the data. 09
Copy-on-write (COW)
Never overwriting a block in place: new versions are written elsewhere and the parent pointers updated, up to the root. 03
CRUSH
Ceph's deterministic placement function over a weighted hierarchy of failure domains, using straw2 at each level. 09

D

Delayed allocation
Choosing disk blocks at writeback time instead of at write() time, so the allocator sees larger runs. 03
Delegation
A server promise that lets a client open and cache a file without asking again, until the server sends CB_RECALL. 07
Deleted-but-open file
An unlinked inode kept alive by an open descriptor, still using space until the last close. 01
Dentry
Cached link from (parent directory, name) to an inode, or to nothing. 05
Directory entry
A variable-length record pairing a name with an inode number inside a directory block. 03
Dirty page
Cached data changed in RAM and not yet written to the device. 05
Discard / TRIM
A command telling a device that a range of LBAs no longer holds useful data. 02
DMA
A device copies to or from RAM by itself, using physical or IOMMU addresses of pinned pages. 08
Doorbell
A memory-mapped write that tells the NIC (or an NVMe drive) new work is waiting. 08
Duplicate request cache (DRC)
The server's cache of recent replies, used to answer retransmitted non-idempotent requests. 06

E

Erasure coding
k data chunks plus m coding chunks; survives any m losses at (k+m)/k raw overhead. 09
errno
Per-thread error code. The kernel returns −errno; the libc wrapper turns that into −1 plus errno. 01
errseq_t
Per-file writeback error counter that lets fsync report each error once per open file. 05
ESTALE
Stale file handle: the server no longer recognises a handle, usually because the file was removed or replaced. 06
Extent
One run of contiguous blocks, described as (file block, length, disk block). 03
Extent tree
ext4's B+tree of extents, rooted in the inode's 60-byte i_block. 04

F

Fanout
The number of children one tree node can point to: node size divided by entry size. 04
Fencing
Making a suspected-dead node harmless (power off, storage cut-off, blocklist, epoch) before taking over its work. 09
File descriptor (fd)
A small integer that indexes the process's table of open files. 01
File handle
An opaque ID the server issues for a file (up to 64 bytes in v3, 128 in v4), usually encoding filesystem id, inode and generation. 06
FLUSH / FUA
Make the device's whole volatile write cache durable, or make one write durable before it completes. 02
Folio
A power-of-two run of contiguous pages managed as one unit (Linux 5.16 and later). 05
FRWR
Fast registration: register and invalidate memory through work requests, per I/O, without a system call. 08
fsync / fdatasync
Wait until a file's data, plus all or only the needed metadata, is on stable storage, including a device cache flush. 05
FTL (flash translation layer)
SSD firmware that maps LBAs to flash pages and never overwrites in place. 02

G

Grace period
The window after a server restart when clients may only reclaim the opens and locks they held before. 06
Group descriptor
The per-group entry giving the block numbers of that group's bitmaps and inode table. 03

H

Hard link
A second directory entry for the same inode, counted in i_links_count. 03
Hole
A range of file blocks with no extent, which reads back as zeros. 03
htree
ext4's hashed B-tree directory index, whose root (dx_root) lives in directory block 0. 04

I

Inline threshold
The largest RPC message sent in a plain SEND; anything bigger needs chunks. 08
Inode
The fixed-size record holding a file's type, permissions, size, timestamps, link count and block map. 03
Inode number arithmetic
group = (ino − 1) / inodes_per_group; the byte offset follows from the group's inode table block and the inode size. 03

J

jbd2 journal
ext4's write-ahead log: metadata changes commit as transactions and are replayed after a crash. 03

L

LBA (logical block address)
The sector number a device is addressed by, counting from 0. 02
LDLM
Lustre's distributed lock manager; a client may cache only the byte ranges and metadata it holds locks on. 09
Lease
The period (90 s by default on Linux) for which a client's NFSv4 state stays valid without renewal. 06
LSM tree
Buffers writes in memory and merges sorted files in the background instead of updating a tree in place (RocksDB, BlueStore metadata). 04

M

Maple tree
The Linux kernel's in-memory B-tree of address ranges, used for a process's memory map. 04
Memory region (MR)
A registered, pinned buffer. Its lkey lets local work requests use it; its rkey lets a remote peer access it. 08

N

Negative dentry
A cached record that a name does not exist, so repeated misses skip the filesystem. 05
NVMe queue pair
Submission and completion ring buffers in host RAM, driven by doorbell writes. RDMA reuses the same model. 02

O

O_APPEND
Open flag that moves every write to end-of-file atomically first. Atomic on local filesystems only, not on NFS. 01
O_CLOEXEC
Flag that closes a descriptor automatically on execve. 01
O_DIRECT
Open flag for DMA between the user buffer and the device, bypassing the page cache. Needs aligned buffers and offsets. 05
ONC RPC
The remote procedure call framework (RFC 5531) under every NFS message; replies are matched to calls by xid. 06
Open file description
The kernel object (struct file) made by open(), holding the offset and status flags; shared after dup and fork. 01
Operation table
A struct of function pointers a filesystem fills in so the VFS can call it. 05

P

Page cache
The kernel's RAM copy of file contents, shared by read, write and mmap. 05
Placement group (PG)
A Ceph hash bucket of objects within a pool; CRUSH maps PGs, not single objects, to OSDs. 09
pNFS
NFSv4.1 feature where a metadata server hands out layouts so clients read and write the data servers directly. 06

Q

Queue pair (QP)
A send queue plus a receive queue: the RDMA endpoint. It must move RESET → INIT → RTR → RTS before use. 08
Quorum
A majority of a small odd-sized group must agree, so at most one side of a network split can make changes. 09

R

RCU walk
Lock-free path lookup through the dcache that falls back to a reference-counted walk when something changes. 05
RDMA
A NIC reads or writes another machine's registered memory directly, with no remote CPU or kernel on the data path. 08
Readahead
Fetching file data before it is asked for, triggered by sequential access. 05
Read-modify-write
Reading a whole unit to change part of it, caused by small or misaligned writes. 02
Read / write / reply chunk
Memory the client advertises so the server can pull bulk arguments, or push bulk results and long replies, by RDMA. 08
Reclaim / kswapd
Freeing memory by dropping clean pages, writing dirty ones and swapping anonymous ones. 05
Reliable Connected (RC)
The RDMA transport with acknowledged, in-order delivery between one pair of QPs; the one storage protocols use. 08
RoCE v2
RDMA over Ethernet in UDP/IP packets (destination port 4791), relying on PFC and ECN/DCQCN. 08
RPC-over-RDMA
The RFC 8166 framing that carries ONC RPC, and so NFS, over RDMA, with credits and chunk lists. 08
RPCSEC_GSS
Kerberos security for RPC: krb5 authenticates, krb5i adds integrity, krb5p adds encryption. 06

S

Server-side copy
NFSv4.2 COPY, triggered by copy_file_range(): the server copies the data without sending it through the client. 06
Session slot table
NFSv4.1 per-slot sequence numbers and cached replies that give exactly-once semantics. 06
Silly rename
The NFS client renaming an unlinked file it still has open to .nfsXXXX, and removing it at the last close. 07
Sparse file
A file with holes: ranges with no disk blocks that read back as zeros. 01
Stateid
A 16-byte NFSv4 identifier for an open, lock, delegation or layout, sent with READ, WRITE, LOCK and CLOSE. 06
Striping
RAID 0 of a file's bytes across several data servers, set by stripe size and stripe count. 09
super_block
In-memory object for one mounted filesystem instance; carries its super_operations. 05
Superblock
The 1 KiB record at byte 1024 holding the filesystem's sizes, counts, features and the magic number 0xEF53. 03
System call
A request from a user program to the kernel, made with the syscall instruction: number in rax, arguments in registers. 01

V

VFS (virtual file system)
The kernel layer that turns file syscalls into calls on a specific filesystem's operation tables. 05

W

Write amplification
The ratio of flash writes to host writes, raised by garbage collection. 02
Writeback
Flusher threads writing dirty folios to the device on thresholds, on age, or on fsync. 05
Write verifier
An 8-byte value in WRITE and COMMIT replies that changes when the server restarts, telling clients to resend uncommitted data. 06

X

XArray
The radix tree that indexes a file's folios by page index. 05
XDR
Big-endian, 4-byte-aligned encoding of RPC arguments, with no field tags on the wire (RFC 4506). 06
